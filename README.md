## Авторизация

Реализована форма входа с обязательной валидацией полей:

- логин
- пароль

Если API возвращает ошибку, сообщение отображается в интерфейсе.

### Логика `Remember me`

- если чекбокс включён, токен сохраняется в `localStorage`
- если чекбокс выключен, токен сохраняется в `sessionStorage`

Таким образом:

- с включённым `Remember me` сессия сохраняется после закрытия браузера
- без него сессия сбрасывается после закрытия вкладки / завершения сессии браузера

## Защищённый роутинг

Неавторизованный пользователь не может попасть на закрытые страницы приложения.  
При попытке перехода выполняется редирект на страницу логина.

На странице товаров реализованы:

- загрузка списка с API
- поиск
- сортировка по цене
- серверная пагинация
- выделение строк
- добавление товара через форму

### Поиск и сортировка

Поиск отправляется на API с debounce, чтобы не делать лишние запросы на каждый символ.  
Сортировка по цене работает через API и обновляет список товаров с учётом текущих параметров.

## Добавление товара

По нажатию на кнопку **«Добавить»** открывается модальное окно с формой.

Доступные поля:

- Наименование
- Цена
- Вендор
- Артикул

После успешного добавления:

- новый товар появляется в списке
- показывается toast-уведомление

## Особенности реализации

### Таблица
Таблица построена на `TanStack Table` и поддерживает:

- кастомные ячейки
- кастомные header cells
- выделение строк
- выделение всех элементов текущей страницы
- синхронизацию чекбоксов строк и header

### Цена
Цена форматируется в удобный вид:

- с пробелами между тысячами
- с выделением дробной части
- с конвертацией в рубли при отображении

### UI / UX
- сохранены предыдущие данные во время подзагрузки
- при повторных запросах показывается progress bar
- формы валидируются до отправки
- ошибки отображаются явно и понятно

## Архитектура

Проект организован по принципам **FSD (Feature-Sliced Design)**.

Примерно по слоям:

- `app` — инициализация приложения, роутинг, провайдеры
- `pages` — страницы
- `widgets` — крупные UI-блоки
- `features` — пользовательские сценарии
- `entities` — бизнес-сущности
- `shared` — переиспользуемые компоненты, утилиты, конфиг

Такой подход помогает:

- не смешивать бизнес-логику и UI
- делать код понятнее для новых разработчиков
- упрощать масштабирование проекта
